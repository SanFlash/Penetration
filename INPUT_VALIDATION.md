# Input Validation Assessment\n\nThe pentest profile now includes a bounded **valid/invalid input-validation phase**.\n\n## What it checks\n\nFor already-discovered same-origin GET query parameters it:\n\n- classifies parameters into text, numeric, email, boolean, date and identifier profiles;\n- sends one profile-valid value;\n- sends several deliberately invalid values;\n- records status codes and response sizes;\n- detects controlled 5xx responses and common exception/database signatures;\n- records invalid values accepted with 2xx as **manual-review observations**, not automatic vulnerabilities.\n\n## Safety\n\nThis phase is intentionally more aggressive in coverage, but remains non-destructive:\n\n- GET only;\n- same-origin enforcement;\n- bounded probe budget;\n- rate limiting;\n- redirects disabled;\n- no form submission;\n- no POST/PUT/PATCH/DELETE;\n- no credential attacks;\n- no DoS/resource exhaustion behavior.\n\nEvidence is written to `evidence/input_validation.json` and included in the pentest report metadata.\n\n## Example\n\n```powershell\n.\\.venv\\Scripts\\python.exe .\\main.py --target https://amwebtech.com --profile pentest --confirm-authorized\n```\n
